# SmartKB 重新发布手册（api / web 改动后如何部署到虚机）

> 适用环境：Windows 开发机（`E:\code\ai\CompanyAI`）→ Ubuntu 虚机（`user@<虚机IP>`，Docker Compose 三容器：db / api / web）
> 原则：**源码包整体替换，`.env` 和数据库卷永远不动**。

---

## 一、改动后的标准发布流程（5 步）

以下命令在 **Windows 的 Git Bash** 里执行（`/e/code/ai` 即 `E:\code\ai`）。

### 第 1 步：本地编译验证（改了 C# 才需要）

```bash
cd /e/code/ai/CompanyAI
dotnet build src/SmartKB.AI/SmartKB.AI.csproj --nologo -v q   # AI 层改动
dotnet build src/SmartKB.Api/SmartKB.Api.csproj --nologo -v q # Api 层改动
```

0 错误才继续。前端（web）改动不需要本地构建，镜像里会自动 `npm install && npm run build`。

### 第 2 步：打部署包

```bash
tar -czf /e/code/ai/SmartKB-deploy.tar.gz -C /e/code/ai/CompanyAI \
  --exclude='web/node_modules' --exclude='web/dist' \
  --exclude='.workbuddy' --exclude='**/bin' --exclude='**/obj' \
  --exclude='tests' --exclude='docs' .
ls -lh /e/code/ai/SmartKB-deploy.tar.gz
```

### 第 3 步：上传并解包（关键：先备份 `.env`）

```bash
scp -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no \
  /e/code/ai/SmartKB-deploy.tar.gz user@<虚机IP>:~/SmartKB-deploy.tar.gz

ssh -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no user@<虚机IP> '
set -e
cp ~/smartkb/.env ~/smartkb.env.bak          # 备份 .env（含 API Key 和密码）
rm -rf ~/smartkb && mkdir ~/smartkb
tar -xzf ~/SmartKB-deploy.tar.gz -C ~/smartkb
cp ~/smartkb.env.bak ~/smartkb/.env && chmod 600 ~/smartkb/.env && rm ~/smartkb.env.bak
echo UNPACK_OK'
```

> ⚠️ **`.env` 不在代码仓库里，删包重建目录前必须先备份**，否则 API Key 全丢。
> 部署包里没有 `.env`，不会覆盖；但 `rm -rf ~/smartkb` 会把它一起删掉，所以顺序必须是：备份 → 删 → 解包 → 还原。

### 第 4 步：重建并启动

```bash
ssh -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no user@<虚机IP> \
  "cd ~/smartkb && docker compose up -d --build"
```

首次/大改动约 5–10 分钟；日常小改动有 Docker 层缓存，约 2–3 分钟。db 容器不受影响，数据不丢。

### 第 5 步：验证

```bash
ssh -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no user@<虚机IP> \
  "cd ~/smartkb && docker compose ps && curl -s -o /dev/null -w 'health: %{http_code}\n' http://localhost/health"
```

- 三个容器 `Up`（db 显示 `Up (healthy)`），health 返回 **200**
- 浏览器访问 `http://<虚机IP>/`，**Ctrl+Shift+R 强刷**（避免命中旧的前端 js 缓存）

## 二、只改一个服务时的加速版

### 只改了后端（C#）→ 只重建 api

```bash
ssh -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no user@<虚机IP> \
  "cd ~/smartkb && docker compose up -d --build api"
```

### 只改了前端（Vue）→ 只重建 web

```bash
ssh -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no user@<虚机IP> \
  "cd ~/smartkb && docker compose up -d --build web"
```

> 即便只重建单服务，也建议走完整解包流程（第一~三步），保证虚机源码和仓库一致，不留 sed 临时补丁。

## 三、出问题怎么回滚

**容器起不来（新代码有 bug）**：虚机源码是刚解的新包，无法直接回滚。最快的方式是在开发机 `git checkout` 到上一个可用提交，重走第 2–4 步。

**只改坏了 `.env`**：数据卷和密码无关，改回 `.env` 后 `docker compose up -d`（不用 `--build`）即可。

**数据库结构变更**（EF Core 迁移）：api 启动时自动迁移。若迁移失败导致 api 崩溃，看日志定位：

```bash
ssh -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no user@<虚机IP> \
  "cd ~/smartkb && docker compose logs api --tail 40"
```

## 四、排障速查

| 症状 | 先看什么 |
|------|----------|
| 502 Bad Gateway | `docker compose ps` 看 api 是否 Restarting → `logs api` 看启动异常 |
| 提问答错/无引用 | api 日志搜 `ERR`；确认 `.env` 两把 Key（Agnes 对话 / 硅基流动·智谱 向量化） |
| 页面白屏或旧样式 | Ctrl+Shift+R 强刷；不行就确认 web 容器是否真的重建了 |
| compose 报变量缺失 | `cat ~/smartkb/.env` 核对，缺行补行；`docker compose config --quiet` 验证 |
| 构建卡在拉镜像 | 虚机 DNS：`cat /etc/resolv.conf` 应为 223.5.5.5；`docker run --rm hello-world` 验证 |

## 五、当前虚机状态备忘

| 项 | 值 |
|----|-----|
| 虚机 | `user@<虚机IP>`（SSH 免密已配） |
| 代码目录 | `~/smartkb` |
| 访问地址 | `http://<虚机IP>/`（admin 登录，初始密码见 `.env` 的 `ADMIN_INITIAL_PASSWORD`） |
| LLM 对话 | Agnes（`LLM_AGNES_API_KEY`，OpenAI 兼容 `https://apihub.agnes-ai.com/v1`） |
| 向量化 | 硅基流动 `BAAI/bge-m3` 或智谱 `embedding-3`（看 `.env` 的 `LLM_BASE_URL`/`LLM_EMBEDDING_MODEL`） |
| 数据 | PostgreSQL 卷 `pgdata`，与容器生命周期解耦，重建容器不丢数据 |
